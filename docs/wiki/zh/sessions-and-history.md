每个对话都有一个 `session_id`。会话、消息、工具调用、附件、思考内容与会话摘要都保存在当前工作区的 SQLite 数据库里：`<workspace>/.data/chat.db`。切换工作区就切换了历史。

## 新建对话

点顶部工具栏的**新建对话**：

- 生成新的 `session_id`；
- 清空当前消息列表、附件与输入框；
- 不删除旧会话，它仍在**历史**里；
- 保留当前工作区、模型与工具设置。

切换工作区同样会落到一个新会话上，所以新工作区不会一打开就显示另一个目录的对话记录。

## 历史面板

点顶部工具栏的**历史**。面板是一条统一的扁平行列表：开头的搜索图标和一个清除按钮、一组分段标签页，每行右侧是相对时间（悬停显示完整日期）。

### 搜索

搜索框匹配：

- 会话标题；
- `session_id`；
- 消息内容（SQLite 内容检索，输入有 180 ms 防抖）。

默认标题取自第一条用户消息。多模态消息取文本部分；只有附件时显示「(attachment)」。

### 标签页

| 标签 | 内容 |
| --- | --- |
| 全部 | 所有未删除的会话 |
| 收藏 | 标记为收藏的会话 |
| 归档 | 标记为归档的会话 |

收藏与归档是会话元数据，不会移动或删除消息。

### 会话操作

每个会话上的菜单/按钮：

| 操作 | 说明 |
| --- | --- |
| 重命名 | 修改显示标题，存入 `session_meta` |
| 收藏 / 取消收藏 | 加入/移出收藏标签页 |
| 归档 / 取消归档 | 加入/移出归档标签页 |
| 删除 | 删除该会话的消息与元数据，随后加载相邻会话 |

### 生成中禁止切换

回复流式输出期间，历史项不可点击，并提示「请先停止生成再切换历史会话」。这样上一轮的流事件不会被写进新会话：每个回合级事件都带着发出它的 `session_id`，前端会丢弃发往其它会话的数据。

## 消息级操作

### 重试

当最后一条是**用户消息**且这一轮没有完成（请求失败、被停止、应用重启）时，这条消息上会出现**重试**。它把同样的内容作为新一轮发送；失败那次的尾部会先被截掉，对话保持可读。

### 导出 PDF

助手消息上的导出按钮会把回复写成**真正的 PDF 文件**（不再走系统打印对话框）：渲染后的 Markdown/HTML——代码块、表格、公式都在内——生成 PDF，由你选择保存位置。Markdown 编辑器导出草稿同理。

### 删除消息

持久化的消息可以逐条删除。该行从数据库移除；后面的消息仍在，但上下文会出现缺口。

### 从消息分叉

持久化消息上的**分叉**按钮：

- 新建一个截止到该消息的会话；
- 复制该消息及之前全部历史；
- 原会话保持不变；
- 适合回到某个决策点换一种问法。

## 会话交付物

当某一轮跑了子智能体或其它后台工作，它们产出的文件会作为该会话的**交付物**保留；任务面板按会话列出它们，标题栏 `⋯` 菜单可以打开交付物目录（`.data/deliver`）。交付不会删除它们，长任务事后仍可检查。

## 历史与工作区

- 历史数据库是**按工作区隔离**的：`<workspace>/.data/chat.db`。
- 切换工作区后面板会重新查询，不显示上一个工作区的会话。
- 默认工作区是应用数据目录下的 `workspace/`；自定义工作区在「设置 → 工作区与配置」里选。
- 保存的工作区路径若已不存在（被移动、改名、卸载），应用会回退到应用数据目录的工作区而不是报错；到设置里重新选一次目录即可。
- 删除工作区目录会一并删掉历史、记忆、待办和技能。先导出备份。

## 数据保留

- **聊天历史从不自动清理。**
- 请求/交互日志跟随「设置 → 调试 → 日志保留天数」（默认 90 天；`0` 表示永久保留）。
- 交互监视器里的**压缩数据库**只删除过期日志并执行 `VACUUM`，不会动聊天历史。

见 [监控与日志](监控与日志)。

## 备份与迁移

两种方式：

1. **完整导出**：标题栏 `⋯` → **导出配置方案…**。压缩包里包含 `chat.db` 快照、配置、MCP、子智能体、技能、记忆和待办。换机器或整机恢复用这个。
2. **手动复制**：关闭应用后复制 `<workspace>/.data/chat.db`。只够恢复历史，不含配置与技能。

细节见 [配置与备份](配置与备份)。

## 常见问题

| 现象 | 原因 |
| --- | --- |
| 切换工作区后历史为空 | 历史按工作区隔离；切回去即可 |
| 列表只有标题没有内容 | 列表只存首条消息的轻量摘要；打开会话看完整消息 |
| 删除会话后磁盘没变小 | SQLite 不会立即收缩；用**压缩数据库** |
| 分叉后原会话变了 | 分叉只应复制；若发生，检查 `session_id` 与数据库 |
| 没有重试按钮 | 只有最后一条是未完成的用户消息时才出现 |
| 出现了别的会话的回复 | 不应该：回合事件按会话隔离——请带上 [监控与日志](监控与日志) 里的请求 id 反馈 |
