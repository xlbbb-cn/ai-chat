工作区是 Rabbit Chat Studio 的核心边界：技能、记忆、待办、聊天历史，以及文件工具用的相对路径，都以它为基准。切换工作区就切换了整套状态。

## 工作区是什么

- 磁盘上的普通目录，通常就是你的项目根目录。
- 文件工具、命令执行、CLI 子智能体和 stdio MCP 服务器都在这里启动。
- 应用会在其中创建隐藏的 `.data/` 目录，存放工作区级状态。
- 标题栏显示文件夹名，下面一条细红线；原生窗口标题是 `Rabbit Chat Studio — <完整路径>`。
- 标题栏 `⋯` → **打开工作区目录** 会在文件管理器里定位它。

## 默认位置与改动方式

| 情况 | 路径 |
| --- | --- |
| 未设置 `workspace_dir` | `<应用数据>/workspace/` |
| 自定义 | **设置 → 工作区与配置 → 工作区目录** |

目录输入框旁边是最近使用的工作区选择器（`workspace_history`，新的在前，最多 10 个）。选中只是暂存，点**保存修改**才真正切换。每次切换都会记录，并随配置方案备份一起带走。

如果启动时保存的路径已经不存在（目录被移动、改名或卸载），应用会回退到 `<应用数据>/workspace/` 而不是启动失败；标题栏会显示那个目录，你可以再到设置里选回真实目录。

应用数据目录：

| 平台 | 路径 |
| --- | --- |
| Windows | `%APPDATA%\com.leonard.aichat\`（Roaming） |
| macOS | `~/Library/Application Support/com.leonard.aichat/` |
| Linux | `~/.local/share/com.leonard.aichat/` |

> 从 Microsoft Store 安装的是 MSIX 包，Windows 会把上面的路径重定向到 `%LOCALAPPDATA%\Packages\XLBBB.RabbitChatStudio\LocalCache\Roaming\com.leonard.aichat\`。所以商店版和 GitHub 安装包版**看不到对方的应用配置**，而工作区里的 `.data` 目录是共享的——换安装方式看起来就像首次启动。

**重置**会清空 `config.workspace_dir` 并回到默认工作区。在影子窗口里（见 [配置与备份](配置与备份) 的「多窗口」），重置回到该窗口自己的分叉配置，永远不会回到共享的默认工作区。

### 切换时发生什么

保存新工作区之后：

1. 应用关闭当前 SQLite 连接，打开 `<新工作区>/.data/chat.db`。
2. 历史、请求监控、交互日志与智能体任务切到新数据库。
3. 技能及其启用状态切到新工作区的 `.data/skills` 与 `skills.status`。
4. 记忆与待办切到新工作区的 `.data/memory` 与 `.data/todos`。
5. 待触发定时器写回旧工作区的 `.data/timers.json`，新工作区的那组被装载；逾期的立即触发。
6. 运行中的 stdio MCP 子进程被停止；下一次工具调用在新工作区重新拉起。
7. 历史面板重新查询，标题栏更新，并落到一个新会话上——新工作区不会一打开就是上一个目录的对话记录。

> 切换不会移动旧的 `.data` 目录。要迁移请复制它，或用**导出配置方案 / 恢复配置方案**。

## `.data` 布局

```text
<workspace>/
  .data/                       （隐藏；属于工作区）
    chat.db                    SQLite：history / api_requests / interaction_log / agent_missions …
    memory/
      user/<key>.md            user 作用域长期记忆
      repo/<key>.md            repo 作用域长期记忆
      evolution/<key>.md       evolution 作用域记忆（仅自我进化模式）
    todos/
      <session_id>/
        .active                当前清单 id
        lists/<list_id>.json   清单内容
    skills/
      <folder>/skill.md        唯一的技能根目录（也接受 SKILL.md）
    skills.status              本工作区的技能启用状态与元数据
    timers.json                本工作区待触发的延时定时器
    scripts/                   run_cmd 脚本库（裸名脚本，启动时创建）
    mcp/
      <slug>/server.*          自建 MCP 服务器脚本（自我进化模式）
    mcp.conf                   这些服务器的名册（与应用数据的 mcp_servers.json 合并）
    deliver/
      <session-id>/<batch-id>/ 子智能体交付物交换区：shared/ + 每个任务一个目录
    tmp/
      pdf/<stem>-<digest>.md   缓存的 @ 提及 PDF→Markdown 转换
```

`scripts/`、`tmp/` 与 `deliver/` 在启动时创建。`deliver/` 与其会话同寿——它纳入配置备份，会话删除时一并消失；可从标题栏 `⋯` 菜单（**打开交付物目录**）或任务监视器刷新按钮旁进入。`tmp/` 是纯草稿区：直接放在其中的普通文件一天后过期。脚本库会列给模型，也纳入配置备份。

Windows 上该目录带隐藏属性；macOS/Linux 靠点前缀隐藏。

### `.data` 在工作区里面

助手的文件工具能像访问普通目录一样访问 `.data`：

- `file_actions` 可以列出、搜索、读取**和写入**它——助手能查自己的技能、记忆和待办清单，并直接管理它们；
- **唯一的例外**是工作区数据库（`.data/chat.db` 及其 `-wal`／`-shm`／`-journal` 附属文件）。`file_actions` 对它只能截断或删除、无法改写，所以会被拒绝——里面是聊天历史、请求监控、交互日志和智能体任务；
- 工作区根目录本身依然不能被删除或覆盖。

有对应面板的文件（历史、监控、记忆、待办、技能）请用应用自己的面板操作，它们会保持格式和索引一致。数据库没有这样的面板，这正是它被保护的原因。

## 应用数据目录

应用级文件不在工作区里：

| 文件 | 内容 |
| --- | --- |
| `config.json` | 模型、API、工具、工作区、外观、日志保留 |
| `mcp_servers.json` | MCP 服务器定义 |
| `sub_agents.json` | 子智能体与编排 |
| `profiles.json` | 应用内**配置方案** |
| `agents/` | `llm` 智能体定义（Markdown）+ `index.yaml` 发现清单 |
| `shadow/` | 主实例锁 + 每个额外窗口一份分叉配置 |
| `app-<日期>.log` | Debug 构建日志，一天一个文件（Release 默认不写） |
| `workspace/` | 默认工作区 |

完整配置字段见 [配置与备份](配置与备份)。

## 工作区与 Git

工作区若是 Git 仓库：

```gitignore
.data/
```

`.data` 里是聊天数据库、记忆、待办和技能启用状态——本地状态，不该提交。想分享技能源，就把它们放在仓库里再复制进 `.data/skills`，或通过配置方案导出分发。

## 工作区 vs 配置方案 vs 备份

| 机制 | 作用范围 | 含技能？ | 用途 |
| --- | --- | --- | --- |
| 工作区 | 一个目录 | 是（`.data/skills`） | 日常按项目隔离 |
| 配置方案 | 应用级 `profiles.json` | **否** | 快速切换工具、子智能体、MCP |
| 导出压缩包 | 应用 + 当前工作区 | 是 | 换机器、完整备份 |

配置方案保存 `selected_tools`、子智能体、编排与 MCP 服务器。技能选择属于工作区状态，不在配置方案里。

## 迁移工作区

### 方案 A：完整导出/导入（推荐）

1. 在旧工作区打开应用。
2. 标题栏 `⋯` → **导出配置方案…**，保存压缩包。
3. 在新机器/新工作区打开应用。
4. `⋯` → **恢复配置方案…**，选择该压缩包。
5. 导入会先应用 `config.json`（可能因此切换工作区），再把 `workspace/` 状态恢复到新工作区。

压缩包内容与当前导入限制见 [配置与备份](配置与备份)。

### 方案 B：手动复制

关闭应用后：

```text
copy <旧工作区>/.data  →  <新工作区>/.data
```

然后在工作区里打开应用。只想要状态、不需要应用配置时适用。

## 磁盘占用

主要来源：

- `chat.db` 里的聊天历史；
- `api_requests` 与 `interaction_log`（完整请求体可能很大）；
- 记忆与技能文件（通常很小）。

控制手段：

- **设置 → 运行时与调试 → 日志保留天数**（30/90 天；`0` = 永久）；
- 交互监视器 → **压缩数据库** 清理过期日志并执行 `VACUUM`；
- 删除不需要的历史会话。

聊天历史从不自动清理。

## 常见问题

| 现象 | 说明 |
| --- | --- |
| 资源管理器/Finder 里看不到 `.data` | Windows 是隐藏属性；打开「显示隐藏项目」或用终端 |
| 助手说 `.data` 不存在 | 它和其它目录一样能列——让它 `list ./.data` |
| `file_actions` 拒绝 `.data/chat.db` | 工作区数据库被保护：文件工具对它只能截断或删除 |
| 切换工作区后技能不见了 | 技能按工作区隔离；切回去或复制过去 |
| 切换后第一次 MCP 调用很慢 | stdio 服务器被停止，正在新工作区重新拉起 |
| 打开后不是上次的工作区 | 保存的路径已不存在，回退到了应用数据目录的工作区；重新选一次 |
| 删掉的工作区还能恢复吗？ | 只能靠导出压缩包或备份；先备份 |
