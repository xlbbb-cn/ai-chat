Rabbit Chat Studio 在本地记录模型请求与工具调用，所以"模型为什么这么说""工具到底做了什么"都能查。三个界面：交互监视器、智能体任务监视器、诊断日志。

## 交互监视器

打开 **设置 → 调试 → 交互监视器**。

> 只有存在对话会话时该入口才出现；它查询当前 `session_id`。

### 界面

面板与其他界面一样跟随浅/深色主题与当前配色。左侧是交互列表，右侧是详情，下三分之一是当前会话的**会话报告**。

列表项显示：

- 交互类型徽标；
- 执行者（模型名、工具名、MCP 服务器）；
- 动作名；
- 时间戳；
- 错误信息（如有）；
- 输出预览。

详情显示：

| 字段 | 说明 |
| --- | --- |
| 类型 | `llm_api` / `llm_error` / `tool_output` / `mcp_call` / `mcp_response` 等 |
| 执行者 | 模型或工具 |
| 动作 | 如 `chat_completion`、`memory`、`read_file` |
| 时间戳 | 本地时间 |
| 耗时 | 毫秒 |
| 错误 | 失败原因 |
| 输入 | 请求体 / 工具参数，JSON 格式 |
| 输出 | 响应 / 工具结果 |
| 元数据 | 附加信息 |

**会话报告**在 SQL 里聚合同一会话（`get_session_stats` 基于 `api_requests` + `interaction_log`）：总 token、缓存命中/未命中与加权命中率、上下文窗口占用比例、请求数、每轮思考时间、工具流量与最忙的工具。上下文窗口按最新请求的模型查询，未知时显示短横线；没有思考的轮次其推理时间存 `NULL`，所以平均不会被假的 0 ms 稀释。

顶部控件：

- **自动刷新**：每 2 秒；
- **清空日志**：删除 `api_requests` 与 `interaction_log` 的**全部**行（不按会话过滤）；聊天历史不受影响；
- **压缩数据库**：按保留窗口清理并 `VACUUM` 回收磁盘。

### 记录了什么

| 类型 | 触发 |
| --- | --- |
| `llm_api` | 每次成功的 Chat Completions 请求；完整请求体、响应内容、耗时 |
| `llm_error` | 失败请求；错误与耗时（不重复存请求体） |
| `tool_output` | 内置工具结果 |
| `mcp_call` | MCP 工具调用 |
| `mcp_response` | MCP 工具结果 |

`api_requests` 还存一行指标：模型、finish_reason、prompt/completion token、耗时、推理时间（`reasoning_ms`，流式推理后的第一个增量）与首 token 时间（`first_token_ms`），以及错误。交互监视器主要展示 `interaction_log`；日志行里的"· thinking 3.6s"就来自这些列。

### 保留策略

**设置 → 调试 → 日志保留天数**：

- 默认 90 天；
- `0` 永久保留；
- 启动时删除 `api_requests` / `interaction_log` 里超过窗口的行；
- **压缩数据库**再次执行策略并 `VACUUM`；
- **聊天历史 `history` 从不自动清理**。

### 隐私

`llm_api` 的输入含完整请求体：系统提示、对话、附件文本、工具结果都可能在里面。请求体是 `chat.db` 增长的主要原因，也可能含密钥或业务数据。分享 `chat.db` 或导出前先压缩/清空日志。

## 智能体任务监视器

打开 **设置 → 调试 → 智能体任务监视器**。

显示当前会话的任务记录：

| 字段 | 说明 |
| --- | --- |
| 任务 | 根任务描述 |
| 智能体 | 执行它的智能体 |
| 状态 | `running` / `completed` / `stopped` 等 |
| 创建/更新 | 数据库时间戳 |
| 上下文 | 根任务上下文 |
| 活动任务 | 每个任务的 id、名称、描述、状态 |
| 交付物 | 已完成任务留在交换区的文件 |
| 情节摘要 | 执行过程中保存的摘要 |
| 最终报告 | `mark_mission_accomplished` 写入的报告 |

每 2 秒刷新，可手动刷新，还有一个 **交付物文件夹** 按钮打开 `<工作区>/.data/deliver/<会话 id>`（子智能体交付物交换区）以便手动清理。

相关表：

- `agent_missions`
- `agent_tasks`

见 [子智能体](Sub-Agents)。

## MCP 诊断日志

**MCP** 面板 → 某个服务器的 **日志**：

- 内存环形缓冲，重启即清空；
- 记录保存、启动、`initialize`、`tools/list`、`tools/call` 与错误；
- 每 1.5 秒刷新；
- 可手动刷新或清空；
- 测试连接会自动打开日志。

MCP 出问题先看这里：`npx` 下载、PATH、认证、协议握手错误都会出现在此。

## `app-<日期>.log`

位置（`app-<YYYY-MM-DD>.log`，按本地日期一天一个文件）：

| 平台 | 路径 |
| --- | --- |
| Windows | `%APPDATA%\com.leonard.aichat\app-<日期>.log` |
| macOS | `~/Library/Application Support/com.leonard.aichat/app-<日期>.log` |
| Linux | `~/.local/share/com.leonard.aichat/app-<日期>.log` |

说明：

- 商店（MSIX）版下 Windows 会把该路径重定向到 `%LOCALAPPDATA%\Packages\XLBBB.RabbitChatStudio\LocalCache\Roaming\com.leonard.aichat\app-<日期>.log`。
- 只有**调试版**（`cargo` / `tauri dev`）会写；发布版默认关闭。
- **设置 → 调试 → 日志输出** 可在文件与终端（`println`）之间切换；仅调试版。
- 内容含启动、配置应用、工作区切换、MCP 启动、自动接受、上下文压缩、目标循环续跑、请求成功/失败。
- 每行带进程标签（`[primary-<pid>]` / `[shadow-<pid>]`），多开窗口（多实例）写同一个文件时也能区分来源。
- 日期在每次写日志时计算，窗口跨午夜运行会自动切到第二天的文件。
- 启动时按与数据库日志相同的**日志保留天数**设置清理过期文件（`0` 表示永久保留）。旧的 `app.log` 不再写入，原样留在磁盘上。

## 调试流程

### 模型的回答不对

1. 交互监视器 → 最新的 `llm_api`；
2. 在 **输入** 里检查系统消息与历史：系统提示、技能、待办；
3. 看 finish_reason、token 与耗时；
4. 若是 `llm_error`，读错误与 HTTP 状态。

### 工具没跑

1. 有 `tool_output` 条目吗？
2. 没有：模型没调用工具。检查工具开关以及模型是否支持工具。
3. 有但不对：检查工具输入/输出、路径、参数与权限。
4. 卡住：是不是在等确认弹窗？L0–L3 命令 120 秒后超时。

### MCP 工具不可用

1. MCP 面板 → 日志；
2. 看 `initialize` 与 `tools/list` 是否成功；
3. 检查命令/PATH/URL/令牌；
4. 跑一次 **测试连接**。

### 子智能体失败

1. 智能体任务监视器：任务状态与任务错误；
2. 交互监视器：子智能体的工具调用；
3. CLI：进程输出与超时；Cloud：HTTP 错误与轮询状态。

## 常见问题

| 现象 | 说明 |
| --- | --- |
| 监视器是空的 | 本次会话没有交互，或日志被清空 |
| 清空后磁盘没变小 | 删行不会缩小文件；跑 **压缩数据库** |
| 压缩很慢 | 大库上的 `VACUUM` 需要时间；别反复点 |
| 发布版没有 `app-<日期>.log` | 设计如此；用交互监视器与 MCP 日志 |
| 日志里有密钥 | 请求体含提示与工具结果；导出/分享前先清理 |
| 任务监视器里没有任务 | 本次会话没跑子智能体，或编排退回了直接回答 |
