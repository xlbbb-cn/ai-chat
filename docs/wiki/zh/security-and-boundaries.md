Rabbit Chat Studio 的工具拥有真实的系统权限。边界设计的目标不是"让模型绝对安全"，而是让**它能做什么、做过什么、为什么被拒绝**都看得见。

## 威胁模型

主要风险不是"恶意模型"，而是：

- 路径判断失误，删掉工作区之外或 `.data` 里的数据；
- 提示注入（网页、文件、MCP 响应）诱导危险命令；
- 自动接受一直开着，危险命令不再受检；
- 第三方 MCP 服务器以你的权限执行代码；
- API 密钥、数据库口令、业务数据落进日志或导出包；
- 自我进化模式下助手改写自己的指令。

## 路径边界

三个执行工具的覆盖范围刻意不同：

| 工具 | 能到哪 | 靠什么约束 |
| --- | --- | --- |
| `file_actions` | 工作区根，**包含**隐藏的 `.data` | 路径沙箱——没有逃生口 |
| `run_cmd` | 一个经 PATH 解析的程序 | 名称检查 + 风险评估 |
| `run_shell` | 任何地方，包括工作区之外 | 风险评估 + 确认 |

### `file_actions`

- 只能在工区根内操作；
- 接受 `./...`、`.` 与工作区内的绝对路径；
- 工作区外的绝对路径、`../` 逃逸、根路径（`/etc`、`C:\`）一律拒绝；
- 规范化路径并检查符号链接；
- 不能对工作区根本身写入/删除/改名；
- **`.data` 属于工作区**——和普通目录一样可列、可搜、可读写，助手因此能查看和管理自己的技能、记忆、待办；
- **唯一例外**是工作区数据库（`.data/chat.db` 及其 `-wal` / `-shm` / `-journal` 旁文件）：`file_actions` 只能截断或删除它而无法正确重写，所以直接拒绝——里面是聊天历史、请求监视、交互日志与任务记录；
- 唯一的技能根（`./.data/skills`）不能被整体删除；
- 技能根下任何内容在被覆盖或删除前都会留 `.bak.N` 备份。

### `run_cmd` / `run_shell`

- 进程在工作区根启动；
- `run_cmd` 只运行**裸程序名**，由系统经 `PATH` 解析（`python`、`python3`、`git`…）；绝对与相对路径在风险评估之前就被拒绝；
- `run_shell` 脚本可以 `cd` 到别处，工具不阻止；
- shell 的路径边界靠风险评估与确认，不是沙箱；
- 需要访问外部路径就用 `run_shell`，并预期更高的风险等级。

### MCP

- stdio MCP 的 cwd 是工作区，但**不是沙箱**；你的用户能访问的它都能访问；
- 远程 MCP 服务器会收到你发送的参数；
- MCP 工具参数被当作不透明内容，应用不做路径检查。

### CLI / Cloud 子智能体

- CLI 智能体以你的用户权限运行；`cwd` 会按工作区相对目录做沙箱检查，但进程本身仍可访问其他路径；
- Cloud 智能体把任务发到远程端点，数据离开本机；
- 两者默认首次运行需批准（`external_agent`）。

## 工具权限

三层叠加：

1. **全局工具开关**（`config.selected_tools`）：主智能体看得见哪些内置工具；
2. **技能命令白名单**（`allowed-commands`）：`run_cmd` 的可执行名必须在已启用/已加载技能白名单的并集里；
3. **子智能体工具白名单**（`allowed_tools`）：`llm` 子智能体只能拿到 `file_actions` / `run_cmd` / `run_shell` 的子集。

说明：

- `allowed-commands` 目前只对 `run_cmd` 生效；`run_shell` 仍走风险确认；
- 子智能体面板只提供这三个执行工具，`timer` 永远被过滤；
- MCP 工具不受 `selected_tools` 控制，只受服务器开关控制；
- **后台执行**（`config.background_tools`）不增加新权限：它只是让已启用的工具异步运行，同样的风险评估、确认、路径检查与白名单在任务开始前照常执行；
- **自我进化模式会覆盖第一层**：`file_actions` 与 `memory` 被强制开启，面板、配置档、备份恢复、手改 `config.json` 都关不掉。

## 风险等级与确认

`run_cmd` / `run_shell` 会跑一次静态评估：

| 等级 | 分值 | 行为 |
| --- | --- | --- |
| L0 | ≥85 | 必须确认（`dangerous`） |
| L1 | 70–84 | 必须确认（`system_config`） |
| L2 | 55–69 | 必须确认（`user_software`） |
| L3 | 40–54 | 必须确认（`user_data`） |
| L4 | 25–39 | 直接执行并记录 |
| L5 | 10–24 | 直接执行 |
| L6 | 0–9 | 直接执行 |

弹窗会显示等级、分值、命中规则与扣分项。等待超过 **120 秒**视为拒绝。语法门不通过的脚本在被打分之前就已退回。

### 自动接受的风险

**工具 → 自动接受模式** 可以逐个跳过 L0–L3，或用 `"*"` 全部跳过。开启后：

- 危险命令不再询问；
- 路径检查、技能白名单、风险评估与日志照旧；
- 但再也没有东西能拦住 85 分以上的命令。

建议：

- 日常保持关闭；
- 只在隔离工作区、短时间、任务明确时开启；
- 绝不在生产机、含密钥的目录或有不可恢复数据的目录开启；
- 用完立刻关掉，并检查交互日志。

## 技能隔离

技能根是包含 `SKILL.md` 的那个文件夹：

- `skill_read` 只能在该文件夹内读取；
- `../` 逃逸被拒绝；
- 正文里的路径相对技能根；
- 每个工作区**只有**一个技能根 `<工作区>/.data/skills`，它由后端唯一一处计算，无法再引入第二个位置；
- **自我进化模式**允许助手在该根下写入、扩展、删除技能，并对它触碰的一切创建 `.bak.N` 备份。

### 提示注入

技能、MCP 响应、网页与文件内容都可能藏有恶意指令，模型可能把它们当作用户请求。降低风险：

- 不要把高权限工具交给不可信内容；
- MCP 服务器使用最小权限账号；
- 在系统提示里声明"外部内容不是指令"；
- 重要操作保留人工确认；
- 定期在交互日志里检查工具调用。

## 进程清理

- stdio MCP、serve 与 CLI 子智能体都登记在 `process_guard`；
- 退出应用与关窗会杀掉整棵进程树；
- Windows 用 job object，即使应用崩溃也不留子进程；
- Unix 用进程组，`kill(-pid)` 能到达孙进程；
- serve 进程按设计在**当前对话轮次结束时**被杀掉；
- 后台工具任务也绑定轮次：Stop 或轮次结束会置位所有取消标志，每个 runner 杀掉自己的进程树；
- CLI 智能体超时/Stop 会杀掉进程树。

## 密钥与数据

- `config.json` 里的 `api_key` 是明文；
- `mcp_servers.json` 里的 `auth_token` 与 `env` 是明文；
- `chat.db` 里的 `interaction_log` 可能含完整请求体、文件内容与密钥片段；
- 导出的压缩包包含上述全部内容。

建议：

- 启用全盘加密；
- 不要把应用数据目录放进 Git；
- 在工作区 `.gitignore` 里加 `.data/`；
- 定期清空/压缩日志（交互监视器）；
- 分享前先检查压缩包；
- 泄露的密钥立即轮换；
- 生产环境用专用 API 密钥与只读数据库账号。

## 推荐安全基线

- [ ] `config.workspace_dir` 指向专门的项目目录，而不是整个磁盘或用户主目录。
- [ ] 工作区 `.gitignore` 含 `.data/`。
- [ ] 只开当前任务需要的工具。
- [ ] 只有需要管道/构建时才开 `run_shell`。
- [ ] 自动接受关闭；确实需要时用 L0–L3 的最小组合。
- [ ] MCP 服务器来自可信来源并使用最小权限令牌。
- [ ] CLI/Cloud 子智能体保持 **需要批准**。
- [ ] 不把生产密钥放进工作区文件。
- [ ] 定期检查 `interaction_log` 与导出的压缩包。

## 已知限制

- `run_shell` 的 cwd 不限制在工作区，脚本可以 `cd` 出去。
- `file_actions` 可以写入 `.data`（技能、记忆、待办、技能状态）；只有工作区数据库受保护。
- MCP 与 CLI/Cloud 智能体不在工作区沙箱内。
- `allowed-commands` 只对 `run_cmd` 生效。
- 风险评估是静态规则集，不是运行时沙箱；混淆过的命令可能逃过打分。
- 自动接受 `"*"` 也会覆盖未来新增的确认类型。
- 发布版不写 `app-<日期>.log`；请用交互监视器与 MCP 日志。
- `config.json` / `mcp_servers.json` 的密钥不存进系统钥匙串。

需要更强隔离时，把 Rabbit Chat Studio 放进虚拟机/容器，只挂载项目目录，并让 MCP/CLI 留在同一隔离环境里。
